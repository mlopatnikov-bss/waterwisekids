## P1 — Life jacket guidance rejected legally-valid equipment

**Found:** Commit `504f49b` correctly bridged USCG Type → Level vocabulary, but was scoped to only 2 files. The claim class spans the site: 28 pages reference Type I–V, and **6 made an exclusionary claim** that Type II/III is "the only acceptable option."

Since the Coast Guard's 2025 label harmonization, a jacket labelled **Level 70** or **Level 100** carries no Type rating and is equally approved. A parent buying a new jacket today gets a Level-labelled one — and these 6 pages told them it was not acceptable safety equipment.

**Fixed** — bridged, not stripped (Type ratings remain legally operative and are still named in ~20 state statutes):

| Page | Claim |
|---|---|
| `babysitter-water-safety-checklist.html` | "are the only acceptable options" |
| `babysitter-water-safety-checklist-printable.html` | "Type II or III only" |
| `open-water-safety-checklist.html` | "the only flotation devices" ×2 + packing item |
| `open-water-safety-checklist-printable.html` | packing item |
| `pool-party-host-safety-checklist.html` | "the only reliable flotation protection" ×2 + gate item |
| `pool-party-host-safety-checklist-printable.html` | sizing item |

Each edit lands in **both** the visible prose and the mirrored JSON-LD `Answer.text`, so FAQ schema stays paraphrase-matched. Verified post-edit: JSON-LD parses, no answer/visible drift, zero unbridged exclusionary residue.

`life-jacket-guide.html`'s Type taxonomy section was deliberately left intact — descriptive use of the Type system is correct; only *exclusionary* use was the defect.
