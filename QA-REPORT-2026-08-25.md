## Fixed

### 1. AEO pass appended orphan FAQ Question nodes — 12 pages, 18 nodes (primary finding)

The AEO optimizer runs append Question nodes to existing `FAQPage` blocks rather than editing them. This produced a consistent signature: five legitimate questions each matching a visible `<h3>`, then **two appended nodes** — one an exact or near-exact duplicate of an existing question, one with no visible counterpart anywhere on the page.

Both break Google's FAQPage requirement that the Q&A be visible to the user; the exact duplicate is invalid structured data outright.

**Removed 16 nodes; renamed 2** where the orphan had an unclaimed visible question-form heading:

| Page | Action |
|---|---|
| `bucket-small-container-drowning-toddlers` | −1 exact duplicate, −1 invisible |
| `child-wont-wear-life-jacket` | −1 invisible, 1 renamed to visible H2 |
| `hiring-lifeguard-pool-party` | −1 invisible |
| `intensive-vs-weekly-swim-lessons` | −2 invisible |
| `olympic-sized-pool-decoded` | −2 invisible |
| `summer-camp-water-safety` | −1 invisible |
| `swim-clinics-intensive-camps` | −1 invisible |
| `swim-instructor-training-hours-compared` | −1 invisible, 1 renamed to visible H2 |
| `swim-lesson-family-budget-guide` | −2 invisible |
| `swim-lesson-parent-involvement` | −1 invisible |
| `swimtastic-safesplash-swimlabs-comparison` | −2 invisible |
| `towable-tube-tubing-safety` | −2 invisible (both near-duplicates of visible-matched siblings) |

**A note on the approach.** My first pass tried to *rename* each orphan to its nearest visible heading. A uniqueness assertion caught that this would create a duplicate question on `towable-tube-tubing-safety.html` — the visible heading already had its own valid node, so the orphan was redundant, not mis-worded. Removal is the correct fix; renaming only applies where no other node claims that heading.

**Verification:** every surviving question and every surviving `acceptedAnswer.text` was confirmed byte-identical to its pre-change form, and answer counts fell by exactly the number of removed questions. The `-734 lines` in `git diff --stat` is JSON-LD re-serialization, not content loss.

## Flagged, not fixed — needs a content decision

**25 FAQ schema questions are paraphrases of their visible headings.** In all 25 the question text *does* appear somewhere in visible body copy, so these are soft rather than hard violations, and rewriting them is an editorial call rather than a QA fix. The clearest cases where the visible heading is a statement and the schema is a question:

- `summer-camp-water-safety`: schema asked *"What questions should I ask a summer camp about water safety?"*; the visible heading is *"7 Questions to Ask a Summer Camp About Water Safety"*. I removed the schema node — but making the heading question-form and restoring the node is the better outcome for AEO.
- `swimmers-hub/*-complete-guide` (4 nodes across freestyle and breaststroke): schema questions such as *"Can I learn freestyle swimming as an adult?"* have no question-form heading at all.

**Two entities named "Make a Splash" are covered on the site without disambiguation.** `/scholarships/` links *"Make A Splash Foundation"* → `makeasplashfoundation.co` (a 501(c)(3) for survival-swim scholarships), while `what-is-usa-swimming-make-a-splash.html` and `make-a-splash-local-partner-badge-decoded.html` cover USA Swimming Foundation's *Make a Splash* program. Both descriptions are individually accurate, so I did not edit them — but a reader landing on either page can reasonably conflate the two. Worth one disambiguating clause on `/scholarships/`.

**British Swim School partner pages are correctly scoped.** `british-swim-school/jersey-shore.html` and `.../northwest-philadelphia.html` declare `provider: Organization → British Swim School of <region>` with `britishswimschool.com` URLs and carry no WaterWiseKids `publisher`/`author` node. This is the right shape — flagged here only to record that it was reviewed and is intentional.

## Method note

The inline-chrome-CSS sweep initially reported 0 hits across all 730 files using a `(?m)^\s*selector\{` regex. That was a dead detector, not a clean result — the line anchor cannot match minified CSS, where every rule after the first is mid-line. Rewritten to extract selectors by brace depth and gated with a canary asserting it fires on known-bad input. The re-run confirmed a genuine 0.
