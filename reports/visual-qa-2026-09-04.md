## Fixed and pushed

### 1. Page title smaller than its own subheads on mobile — 2 pages
`british-swim-school/jersey-shore.html`, `british-swim-school/northwest-philadelphia.html`

**Before:** h1 **22.4px**, h2 **28px** at 390px — the page title was the smallest heading on screen.
**After:** h1 22.4px > h2 21px, matching the scale `m-app.css:153` documents (h1 22.4 > h2 21 > h3 18.2).

Both pages declare a bare `h2 { font-size: 2rem }` inside their own `<style>` block. That resolves to
28px against the 14px mobile root, while `m-app.css` caps `.page-hero h1` at 1.6rem. `m-app.css`
cannot reach this shape — its heading patches (`m-app.css:1493-1495`) are `h2[style*="…"]` attribute
selectors, which match inline `style=""` attributes only, never a rule in a `<style>` block.

Fixed by appending `@media (max-width:768px){ h2 { font-size:1.5rem; margin-top:2rem } }` to each
page's style block. Screenshots: `mobile-jersey-BEFORE.jpg` / `mobile-jersey-AFTER.jpg`.

> **Note for the next run — the first attempt was inert.** I initially put the override in each
> page's *existing* early `@media` block. It rendered completely unchanged: the bare `h2` rule sits
> ~600 chars later in the same stylesheet, and `@media` adds no specificity, so source order decided
> it. The override must come **after** the bare rule. Only the re-render caught this.

**Scoping is corpus-complete.** Grepping every `<style>` block sitewide for any h2 rule above 22.4px
returned 5 pages; rendering showed `m-app.css` already handles 3 of them (h2 lands at 17.5 / 21 / 21).
These 2 were the only real cases.

### 2. Search-button hover moved the wrong way
`assets/css/main.css:2145` — `.swim-schools-page .search-button button:hover`

The hover background was **lighter** than its `#0369a1` resting state (Δ6/765), so the hover read as
no change at all and inverted the site's convention. Every other button darkens blue-700 → blue-800
(`.btn:hover` main.css:320, `.search-button:hover` main.css:2366). Now `var(--blue-800, #075985)`.
Verified by hover render: `rgb(3,105,161)` → `rgb(7,89,133)`, darker.

Impact is hygiene, not user-facing: the only markup matching this selector lives on
`swim-schools/index.html`, which is a `meta refresh` redirect stub.

### 3. Cache-bust

loaded via JS, so there is no outer-asset chain to bump.
